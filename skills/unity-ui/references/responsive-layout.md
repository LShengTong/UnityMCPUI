# 响应式布局与多分辨率验证

适用于创建新界面或调整现有 UI 布局。工具支持设置锚点不代表 Agent 已经选择了锚点；先确定区域约束，再写参数，最后跨宽高比看结果。

## 主要区域的选择

| 区域意图 | 常用预设 | 配置重点 |
| --- | --- | --- |
| 全屏背景、全尺寸遮罩 | stretch | 使用 offsets 设置边距；图片是否可拉伸按设计判断 |
| 顶部导航条 | stretch_horizontal_top | x 为左右边距，y 为向下的负位置，height 固定 |
| 底部操作条 | stretch_horizontal_bottom | x 为左右边距，y 为向上的正位置，height 固定 |
| 左/右侧栏 | stretch_vertical_left / stretch_vertical_right | y 为上下边距，x 为横向位置，width 固定 |
| 角落关闭按钮、角标 | top_right 等角锚点 | 使用相对父容器的短偏移，避免屏幕中心的大坐标 |
| 居中弹窗、固定卡片 | center | 保持设计尺寸，同时检查窄屏是否越界 |
| 重复条目、工具按钮组 | 父容器锚点 + LayoutGroup | 子节点由父布局管理；用 LayoutElement 控制首选尺寸 |

这张表是选择依据，不是替换既有设计的强制模板。用户的明确尺寸或布局要求优先。锚点相对于父 RectTransform，不是总相对于整张屏幕；父容器本身也要有正确约束。

如主内容需填满导航与底栏之间的空间，使用 stretch，offset_min 表示左/下内边距，offset_max 用负值表示右/上内边距。不要把它设为 center 再填写整张参考图的固定宽高。

创建和新增节点需显式填写关键区域的 anchor。修改已有预设用 batch_edit_ui_prefab 的 modify/anchor，随后设置 offsets 或位置尺寸；anchor 修改会同步 Pivot，但不保持原屏幕边界。父级布局正在驱动的字段不要用反复手动赋值争夺控制。

## 分辨率选择

优先使用用户给出的目标范围，不为仅横屏项目额外承诺竖屏适配。未指定具体尺寸时，可从下列组合选取：

- 横屏界面：1280×720（16:9）和1600×1200（4:3）；需要检查超宽布局时可增加1920×800。
- 竖屏界面：720×1280（9:16）和900×1200（3:4）；长屏可增加1080×1920。
- 1280×720和1920×1080宽高比相同，可验证不同像素密度/缩放，但不能代替跨比例检查。

preview 的每边范围为64..2048像素。大于工具限制的目标可按相同比例缩小预览，并说明没有做原生像素尺寸验证。不得为了截图通过而在两次预览间分别修改同一份布局；最终同一版本应在选定尺寸下都合理。

## 调用和观察

先对同一个保存版本调用 preview_ui_prefab，例如横屏测试：

```json
{
  "asset_path": "Assets/UI/MainMenu.prefab",
  "width": 1280,
  "height": 720,
  "background": "#202020"
}
```

```json
{
  "asset_path": "Assets/UI/MainMenu.prefab",
  "width": 1600,
  "height": 1200,
  "background": "#202020"
}
```

逐张查看，检查：

- 导航、底栏和角按钮是否仍贴在预期边缘，边距是否合理。
- 内容区是否随父容器变化，是否发生意外空洞、重叠或裁切。
- 文字、按钮和图标是否完整；窄屏是否让居中固定面板或横向导航越界。
- Sprite 是否因非等比拉伸变形，九宫格边框是否合理。

若出问题，先用 inspect 检查锚点/Pivot、CanvasScaler、父布局和 LayoutElement；修正约束后重新预览受影响尺寸。inspect 返回保存配置，不是某张截图中的运行时像素边界；不能只凭序列化数值断言屏幕上没有溢出。

锚点无法自动实现断点重排、文字换行策略或运行时数据逻辑。若当前工具无法配置必要能力，说明限制，不声称自动完成这些适配。截图也不验证设备安全区域、输入响应或真实游戏运行状态。

最终说明实际检查的尺寸、发现并修正的问题及仍未覆盖的目标。若客户端不能展示图片或预览失败，说明视觉验证未完成；用户要求暂不验证时尊重要求。
